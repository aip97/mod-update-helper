# 모드 업데이트 도우미 0.7.0

Windows Chrome / Edge에서 설치된 모드를 확인하고, 배포 파일 검사·백업·업데이트·롤백을 수행하는 도구입니다. 사용자용과 모더용 ZIP을 따로 제공합니다.

## 설치와 사용
1. `Mod-Update-Helper-User-0.7.0.zip`을 모두 풀고 `Install.cmd`를 실행합니다.
2. 안내한 고정 `extension` 폴더를 브라우저의 개발자 모드에서 불러오고 **파일 URL에 대한 액세스 허용**을 켭니다.
3. 게임을 열고 도우미를 실행합니다. 인식한 게임 경로를 기본으로 연결하며 **경로 변경**과 **감지 경로 사용**으로 바꿀 수 있습니다.
4. 활성 모드를 한국어·원래 이름·ID로 검색합니다. API가 없어도 모드 설정에서 Kone 게시글 주소를 직접 등록할 수 있습니다.
5. **모두 상태 확인** 후 필요한 모드를 선택해 업데이트합니다. 처음 진행할 때 입력한 Kio 비밀번호는 이 브라우저에 저장합니다. 잠긴 컬렉션은 파일 목록 확인에도 비밀번호가 필요합니다. 비밀번호 없는 공유는 빈칸으로 저장할 수 있습니다.
6. **기본 비밀번호 설정·변경**으로 저장값을 바꿉니다. 개별 모드 입력칸의 변경값은 현재 창에서만 유지합니다.
7. 확인창에서 모드·버전·경로를 확인하고 승인합니다. 파일은 백업 후 교체하며 완료 후 게임을 저장하고 새로고침합니다.
8. 이전 버전으로 돌아가려면 **활성 모드 → 롤백 → 백업 선택**을 사용합니다. 동봉 이미지팩도 함께 복원합니다. 다른 작업으로 수정된 파일은 덮어쓰지 않습니다.

도우미 자체는 최초 설치 후 서명된 GitHub Releases를 확인합니다. 새 버전은 업데이트 창이 모두 닫힌 뒤 적용하고 확장 프로그램만 다시 시작합니다. 게임 탭은 자동 새로고침하지 않습니다. 서명 불일치·손상·낮은 버전은 거부하며 새 버전의 시작 확인이 없으면 이전 파일로 복구합니다. 배포 저장소 설정이 없는 개발 사본에는 이 기능이 활성화되지 않습니다.

## 게시글 하나로 여러 모드 배포
제목은 자유 형식입니다. 제목·본문의 버전과 파일명은 같을 필요가 없습니다. 게시글을 모드마다 따로 만들 필요도 없습니다. 여러 모드에 같은 게시글 주소를 등록하세요.

본문에는 Kio 컬렉션 주소 또는 그 주소의 Base64를 넣습니다. 컬렉션 하나에 여러 모드 ZIP과 이전 버전을 함께 올릴 수 있습니다. 도우미는 선택한 모드에 해당하는 파일 중 가장 높은 버전을 찾습니다. 같은 최신 버전 ZIP이 여러 개면 임의로 고르지 않습니다.

권장 파일명은 `my-mod 1.2.3.zip`입니다. `my-mod.zip`처럼 버전이 없는 정확한 ID 파일명도 지원하며 이 경우 상태 확인 중 ZIP을 읽어 내부 헤더의 버전을 확인합니다. `Family_Mod_MyFeature_v1.2.3.zip`처럼 구분자·대소문자가 다른 기존 이름은 정규화된 모드 ID가 일치할 때 후보가 됩니다. 최종 설치에서는 내부 ID까지 반드시 일치해야 합니다.

일반 링크 예시(가상 주소이므로 실제 링크로 교체):
```text
제목: 모드 모음 업데이트

본문:
다운로드: https://kio.ac/c/abcdefghijklmnopqrstuv
```

본문에서 최대 8개 컬렉션을 검사합니다. Kone은 발행된 `https://kone.gg/s/<공간>/<22자리ID>` 직접 주소를 사용합니다. Kio는 HTTPS 공유 주소를 사용하고 쿼리·fragment·자격 증명을 붙이지 않습니다. **게시글 진단**에서 접근·링크·파일명을 확인할 수 있습니다. ZIP 내용은 별도 검증하며, 버전 없는 파일은 진단 중에도 읽기 검사를 합니다.

## 모드 헤더와 게임 호환
주석·공백 뒤 `WML.define({`로 시작하고 첫 12,000자 안에서 `symbols` 또는 `setup` 전에 메타데이터를 선언하세요.

```js
WML.define({
  id: 'my-mod',
  name: {ko: '내 모드', en: 'My Mod'},
  version: '1.2.3',
  game: 'harbor>=1.2.0',
  wml: ['0.9.4', '0.9.5'],
  async setup(api) {
    // 모드 코드
  },
});
```

`setup(api) {}`, `async setup(api) {}`, `setup: async (api) => {}`를 모두 지원합니다. 헤더를 검사하기 위해 코드를 실행하지 않습니다. ID·버전·게임 선언은 리터럴 문자열이어야 합니다. `wml`은 실제로 지원하는 정확한 버전 문자열 또는 중복 없는 배열입니다. 선언이 없으면 호환 미확인으로 별도 확인하고, 지원하지 않는 버전이면 중단합니다.

표준 날짜 빌드의 `game: '>=2026-11-01'`, Faith의 `faith>=3.3.2`, Overtime의 `overtime>=1.0.0`, 새 계열의 `harbor>=1.2.0`과 같은 조건을 지원합니다. `game: '*'`는 실제 모든 계열을 지원하는 모드에만 사용합니다. 로더는 0.9.3 이상과 `WML.currentPreset()` 규약이 필요합니다.

실행한 정확한 HTML의 버전과 로더 프리셋·디스크 빌드를 함께 비교합니다. 새 계열은 `<meta name="wml-game" content="harbor-1.2.3">`를 권장합니다. Faith의 `wf-version`, Overtime의 `ot-version`도 지원합니다. 새 계열과 Overtime은 가상 파일 검사 범위이며 실제 게임 전체 동작을 검증한 것은 아닙니다.

## ZIP 구조와 롤백
다음 진입점을 지원합니다: `mod.js`, `<id>/mod.js`, `mods/mod.js`, `mods/<id>/mod.js`, `wml/mods/mod.js`, `wml/mods/<id>/mod.js`. 바깥의 게임 포장 폴더와 Windows 역슬래시 경로도 지원합니다.

```text
GameFolder/
  wml/mods/my-mod/mod.js
  image-packs/creator-character/mods/my-mod/pack.js
  image-packs/creator-character/mods/my-mod/images/picture.webp
```

모드 파일은 선택한 모드 폴더로 맞추고 함께 든 `image-packs/`는 게임 루트에 설치합니다. 이미지팩의 `pack.js`, JSON, PNG/JPEG/WebP/GIF/AVIF만 허용합니다. 기존 파일 백업, 새 파일 기록, 실패 시 복원과 사용자 롤백에 포함합니다. 게임 전체·다른 모드·서버·실행 파일·저장·설정·캐시는 설치하지 않습니다.

ZIP 256 MiB, 해제 총량 512 MiB, 파일당 16 MiB, 디렉터리 포함 4,096항목이 한도입니다. Stored/Deflate와 검증된 Unicode 파일명·표준 날짜/소유자 메타데이터를 지원합니다. ZIP64·암호화·분할·데이터 디스크립터·링크·상위 이동·중복 경로는 거부합니다.

동봉 Python 도구는 **배포용 모드 폴더**를 검사하고 표준 경로 ZIP을 만듭니다. 기존에 호환되는 이미지팩 동봉 ZIP을 다시 포장할 필요는 없습니다.
```text
python examples/package-mod.py <배포용-모드폴더> <출력폴더> --id my-mod --version 1.2.3
```

## 게임 본체 업데이트
기존 모드 API를 바꿀 필요는 없습니다. 게임 제작자는 별도 WML_GAME_UPDATER 선언으로 배포 게시글과 ZIP·HTML 파일명 규칙을 제공합니다. Faith의 기존 배포 게시글은 기본 연결되어 있습니다. 새 버전 알림 → 배포판 선택 → 다운로드·검사 → 저장 완료 확인 → 게임 탭 종료 → 백업·설치 → 사용자가 게임 다시 열기 순서입니다.

[게임 본체 가이드](GAME_UPDATE.md)에 API 코드, 보호 경로, 게임 ZIP 한도와 복구 범위를 정리했습니다. [복사용 코드](examples/game-update.js)를 실제 게임의 값으로 바꿔 사용하세요. 본체 설치에는 Windows 로컬 도우미가 필요하며 실행하던 HTML의 실제 경로를 사용합니다.

## 모더 자료
`GUIDE.html`에는 실제 게시글 캡처와 코드 예제가 포함됩니다. `examples/release-post.txt`는 여러 모드를 한 글에 배포하는 예시입니다. 선택적 API 연동은 [AI 연동 안내](AI_MOD_INTEGRATION.md)와 [계약](skills/wml-updater-integration/references/contract.md)을 참고하세요. API가 제공하는 유효한 게시글 주소가 수동 주소보다 우선합니다.

브라우저에 따로 설치된 모드 사본은 폴더보다 우선할 수 있습니다. 폴더 모드를 사용해야 합니다. 백업은 게임 폴더의 `.wml-mod-updater-backups/`에 저장하며 게임 세이브를 되돌리지는 않습니다.

선행 설정 이관 코드가 있어도 첫 12,000자 안의 최상위 WML.define을 실행하지 않고 읽습니다. 선행 정규식·나눗셈·동적 템플릿과 IIFE 안의 정의는 추측하지 않으므로 선언을 앞에 두세요.
