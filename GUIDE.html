모드 업데이트 도우미 0.7.3 · 모더 가이드

게시글 한 개와 컬렉션 하나로 여러 모드의 업데이트를 배포할 수 있습니다. 사용자용 도우미는 파일 검사, 백업, 업데이트와 롤백을 제공합니다.

1. 게시글 제목은 자유롭게

제목에 모드 ID나 버전을 넣을 필요가 없습니다. 본문에 Kio 공유 주소 또는 그 주소의 Base64를 넣으세요. 여러 모드에 같은 게시글 주소를 등록할 수 있습니다.

제목: 모드 모음 업데이트
본문: 다운로드: https://kio.ac/c/abcdefghijklmnopqrstuv

컬렉션:
my-mod 1.2.3.zip
another-mod 2.0.0.zip

위 주소는 가상 예시입니다. 실제 공유 주소로 바꾸세요. 최대 8개 컬렉션을 읽으며 선택한 ID의 최신 파일 버전을 찾습니다. 동일 최신 버전이 중복되면 중단합니다. my-mod.zip은 상태 확인 중 ZIP의 헤더를 읽습니다. 구분자·대소문자가 다른 기존 파일명도 ID가 일치하는 후보는 검사합니다. 최종 내부 ID·버전 검사는 생략하지 않습니다.

2. 실제 게시글 예시

요청한 원문 게시글을 2026-11-03에 캡처한 화면입니다. 화면의 모드·버전·주소는 작성 예시이며 지금의 배포 상태를 보장하지 않습니다.

컬렉션에 여러 모드를 함께 업로드하면 각 모드는 자신의 ID로 파일을 찾습니다. 버전별 게시글을 새로 만들거나 모드마다 글을 나눌 필요가 없습니다.

3. 모드 헤더

첫 12,000자 안에서 symbols/setup 전에 id·version·game을 리터럴 문자열로 선언합니다. async setup(api) {}와 setup: async (api) => {}를 모두 지원합니다.

WML.define({
  id: 'my-mod',
  name: {ko: '내 모드', en: 'My Mod'},
  version: '1.2.3',
  game: 'harbor>=1.2.0',
  wml: ['0.9.4', '0.9.5'],
  async setup(api) { /* 모드 코드 */ }
});

wml에는 실제 지원하는 정확한 버전만 넣습니다. 미선언은 호환 미확인으로 표시하며 지원하지 않는 로더면 중단합니다. 실행한 HTML·로더 프리셋·모드의 게임 계열과 빌드도 함께 확인합니다. 표준 날짜 빌드와 Faith, Overtime, 같은 규약을 쓰는 새 계열을 구분합니다.

새 계열은 <meta name="wml-game" content="harbor-1.2.3">를 사용합니다. 기존 wf-version, ot-version도 지원합니다. 새 게임의 실제 실행 호환성은 모더가 확인해야 합니다.

선행 설정 이관 코드가 있어도 첫 12,000자 안의 최상위 WML.define을 실행하지 않고 읽습니다. 선행 정규식·나눗셈·동적 템플릿과 IIFE 안의 정의는 추측하지 않으므로 선언을 앞에 두세요.

4. ZIP과 이미지팩

GameFolder/
  wml/mods/my-mod/mod.js
  image-packs/creator-character/mods/my-mod/pack.js
  image-packs/creator-character/mods/my-mod/images/picture.webp

mod.js를 최상위, 모드 ID 폴더, mods/ 또는 wml/mods/ 아래에 둬도 됩니다. 모드 ID 폴더 생략, 바깥 포장 폴더, 역슬래시 경로를 처리합니다. image-packs/의 pack.js·JSON·이미지 파일은 백업·설치·롤백에 포함합니다. 다른 모드, 전체 게임, 실행 파일, 서버, 저장·설정·캐시는 포함하지 마세요.

한도는 ZIP 256 MiB, 해제 합계 512 MiB, 파일당 16 MiB, 디렉터리 포함 4,096항목입니다. Stored/Deflate와 검증된 Unicode 파일명·날짜 메타데이터를 지원하며 ZIP64·암호화·분할·링크·경로 이동·중복 경로는 거부합니다.

동봉 Python 도구는 모드 폴더를 표준 경로로 포장합니다. 이미 호환되는 이미지팩 동봉 ZIP을 재포장할 필요는 없습니다.

python examples/package-mod.py 배포용모드폴더 출력폴더 --id my-mod --version 1.2.3

5. 사용자 흐름과 확인

비밀번호가 저장되지 않았으면 게임에 연결된 도우미 화면에서 빈 설정창이 나타납니다. 미리 정해 둔 값 없이 사용자가 입력한 하나의 비밀번호를 모든 모드와 게임 본체에 공통으로 사용합니다. 이후 저장값을 사용하며 별도 버튼으로 변경할 수 있습니다. 인식한 게임 경로가 기본으로 연결되고 경로 변경은 따로 제공합니다. 활성 모드는 한국어·원래 이름·ID로 검색할 수 있습니다.

게시글 진단은 접근·공유 링크·파일명을 확인합니다. 버전 없는 파일은 ZIP을 읽습니다. 실제 파일 교체는 사용자 승인 뒤에만 진행하며, 기존 파일을 백업하고 실패하면 복구합니다. 롤백은 선택한 모드와 함께 업데이트된 이미지팩을 복원합니다. 모드와 게임 본체 ZIP은 설치 전에 Microsoft Defender로 검사하며 위협 발견 또는 검사 실패 시 설치를 중단합니다. 0.7.3 이상 Windows 로컬 연결 도우미가 필요합니다. 검사만으로 모든 악성 파일의 탐지나 안전성을 보장하지는 않습니다.

도우미 자체는 최초 수동 설치 뒤 서명된 GitHub 릴리스를 확인합니다. 새 버전이 있으면 화면에서 업데이트 후 재시작할 수 있으며, 다른 도우미 창이 열려 있다면 작업을 마치고 닫은 뒤 다시 시도합니다. 창이 모두 닫힌 상태에서는 자동으로 적용합니다. 0.7.3 이상에서 이후 도우미를 업데이트할 때는 서명·해시 확인 뒤 Defender 검사에도 통과해야 합니다. 최초 설치와 0.7.2 이하에서 0.7.3으로의 업데이트에는 이 자동 검사가 적용되지 않습니다. 게임 탭은 그대로 유지합니다. 저장소가 미설정된 개발 사본에는 자체 업데이트가 활성화되지 않습니다.

6. 게임 본체 업데이트 API

기존 모드 API는 그대로 사용합니다. 게임은 HTML에서 WML을 시작하기 전에 별도 선언을 추가하고 다음 배포에도 유지합니다. 아래 가상 주소·파일명을 실제 배포 값으로 바꾸세요. Faith와 Overtime의 기존 배포 글은 기본 연결되어 있어 게임 코드에 선언을 추가할 필요가 없습니다.

// Declare in the game's HTML before WML starts. Replace the example post URL.
window.WML_GAME_UPDATER = {
  protocol: 1,
  postURL: 'https://kone.gg/s/example/aaaaaaaaaaaaaaaaaaaaaa',
  packages: [
    {id: 'full', label: '전체판', file: 'Harbor_v{version}.zip', html: 'Harbor_v{version}.html'},
    {id: 'light', label: '경량판', file: 'Harbor_Light_v{version}.zip', html: 'Harbor_v{version}.html'},
  ],
  preserve: ['custom-data'],
};

파일명 규칙의 {version}은 harbor-1.2.3이면 1.2.3입니다. HTML의 wml-game 메타와 WML 프리셋·심볼 빌드가 일치해야 합니다. HTML 파일명이 고정이면 html에 index.html처럼 적어도 됩니다. preserve는 추가 사용자 데이터의 상대 경로이며 기본 보호를 해제하지 않습니다.

  1. 사용자가 새 버전 알림에서 전체판·경량판을 고릅니다.
  2. 다운로드·검사 후 버전·경로·모드 호환성 안내를 확인합니다.
  3. 저장 완료·게임과 이미지 서버 종료를 확인하고 설치를 누릅니다.
  4. 같은 게임 폴더의 현재 브라우저 HTML 탭을 닫고 백업·설치·사후 검사를 진행합니다.
  5. 완료 후 게임 다시 열기로 시작합니다.

기존 HTML 파일명과 세이브·설정·wml/mods·프리셋·이미지팩·생성 이미지를 보존합니다. 게임 정적 파일·WML 런타임·서버 소스는 교체할 수 있지만 스크립트를 자동 실행하지 않습니다. 동봉 모드는 모드 업데이트로 따로 배포하세요.

게임 ZIP 한도는 512 MiB, 해제 합계 1 GiB, 파일당 64 MiB, 8,192항목입니다. 본체 설치에는 Windows 로컬 도우미가 필요합니다. 실패나 설치창 연결 종료 시 복원하며, 전원 차단·강제 프로세스 종료는 자동 복구 보장 대상이 아닙니다.

게임 게시글 진단은 ZIP 파일명의 버전 누락도 검사하고 수정할 이름·컬렉션 주소·HTML 예상 위치를 표시합니다. 모드ID.zip은 내부 헤더로 통과할 수 있지만, 빠른 감지를 위해 모드ID 버전.zip 형식을 권장합니다. API 필드·ZIP 구조·보호 경로·예외는 동봉 GAME_UPDATE.md에 정리했습니다. 복사할 코드는 examples/game-update.js입니다.

선택적 모드 API 연동

일반 모드는 API 없이 게시글 주소를 직접 등록할 수 있습니다. 아래 API는 이름·주소를 자동 제공할 때만 필요합니다. 유효한 API 주소가 수동 주소보다 우선합니다.

setup 안에 넣는 연동 코드
// Paste inside your existing WML.define({ setup(api) { ... } }).
// Keep this version equal to WML.define.version for every release.
const updaterVersion = '1.0.0';
const updaterName = '내 모드';
const updaterPostURL = ''; // A valid API URL takes priority; manual URL is only a missing/invalid API fallback.
if (typeof window !== 'undefined' && typeof window.postMessage === 'function') {
  const key = Symbol.for('wml-mod-updater.' + api.id);
  if (typeof window[key] === 'function') window.removeEventListener('message', window[key]);
  const listener = event => {
    const data = event.data;
    if (event.source !== window || !data || typeof data !== 'object' || Array.isArray(data)
      || data.type !== 'WML_MOD_UPDATER_QUERY' || typeof data.requestId !== 'string'
      || !/^[A-Za-z0-9_-]{1,80}$/.test(data.requestId)
      || Object.keys(data).some(k => k !== 'type' && k !== 'requestId')) return;
    let active = false;
    try { active = window.WML.currentPreset().mods.some(mod => mod.id === api.id); } catch {}
    // file:// has an opaque origin. Send only public version metadata and the active flag.
    window.postMessage({
      type: 'WML_MOD_UPDATER_STATUS', requestId: data.requestId, protocol: 2,
      modId: api.id, modName: updaterName, modVersion: updaterVersion, active,
      wmlVersion: String(api.wml), gameVersion: String(api.game),
      ...(updaterPostURL ? {postURL: updaterPostURL} : {}),
    }, '*');
  };
  window[key] = listener;
  window.addEventListener('message', listener);
}
